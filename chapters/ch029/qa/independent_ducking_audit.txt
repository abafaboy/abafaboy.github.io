Independent read-only performance audit: The Lord Who Measured Zero
16 October 2026

Finding
The coordinator's applied cumulative-sum replacement is appropriate for this
production pipeline. The retained original and applied tools/mix.py are identical
outside the ducking smoothing block. No shared project file or process was changed
by this audit. No production build, ffmpeg, synthesis, or audio load was executed.

Sources inspected
- tools/mix.py, retained chapters/ch029/qa/mix.original.py
- tools/build_chapter.py, tools/music.py, tools/cues.py, tools/tts.py
- chapters/ch029/sound.py and timeline.json, CODEX_HANDOFF.md, plan/PIPELINE.md

Exact cost and cause
SR is 44,100; k = int(.25 * SR) = 11,025. The original uses
np.convolve(env, np.ones(k) / k, mode="same"). This direct convolution computes
Theta(N*k) coefficient products, with N*k - floor(k*k/4) contributions for N>=k.
It is linear in chapter duration at fixed sample rate, with a large 11,025 factor;
it is not quadratic in chapter duration. If sample rate is varied while duration
and the quarter-second window are fixed, the work scales as Theta(duration*SR^2).

Ch29 has 27 timeline lines, END=142.515 seconds, N=6,284,911. The direct smoothing
alone entails 69,260,756,119 coefficient contributions. This isolated operation is
demonstrably expensive. The historical stalled process was not sampled, so its
exact instruction pointer cannot be established by this audit.

Replacement
Pad the finite float32 mask with k//2 zeros on the left and (k-1)//2 on the right.
Make a float64 prefix sum P with a leading zero. Output (P[k:] - P[:-k]) / k.
This computes the same N box averages in Theta(N+k) time and Theta(N+k) memory.
Odd and even alignment agree with np.convolve(..., mode="same") for N>=k.
Zero padding and the endpoint reductions in gain are retained. The .42/.18 mask,
speech lead .15s, speech tail .1s, and .25s filter width are unchanged, as are cue
placement, medieval instruments, voices, timing, fades, and normalization code.

For Ch29's mask the float32 constants have a common power-of-two denominator
33,554,432. Even the largest possible prefix numerator is 88,572,377,120,371,
below float64's exact integer limit 9,007,199,254,740,992. Thus prefix accumulation
and subtraction are exact for this two-level mask at this chapter length; the
division and original repeated multiply/sum have different rounding sequences.
Universal bit-for-bit output identity is not claimed.

Independent tests
audit_ducking.py extracts ONLY the smoothing blocks from the two actual source
files and compiles them as isolated functions; it does not import mix.py or any
production module. It verifies source equality outside the replacement, verifies
input immutability, shape and float64 output, and hashes both sources before/after.

276 reference comparisons passed. Kernels: 1,2,3,4,7,8,31,32,127,128,100 and 11025.
Inputs include N=k, N=k+1, zero/gap/speech constants, first/middle/last impulses,
alternating and random two-level masks, signed random float32 values, no speech,
speech at zero, overlaps/touching ranges, fractional indices and a clipped end.
The production-width test uses a two-second SYNTHETIC mask (88,200 samples).
Maximum absolute filter error over all comparisons: 1.7486012637846216e-15.

Two synthetic stereo downstream comparisons (silent voice and voice+FX causing
peak normalization) include music normalization, float32 ducking multiplication,
voice normalization, final 1.5s fade and final peak normalization in source order.
Both produced bitwise-identical float32 music and mixes and zero differing PCM16
samples. PCM16 was encoded/read entirely in memory. These are bounded tests, not
a claim that every possible floating-point audio stream is bitwise identical.

Independent timings, existing Python 3.12.14 / NumPy 2.3.5, no settings changes
Three runs each, k=11,025, wholly synthetic inputs; medians:
  N=22,050: original 2.314363900s; applied 0.000360200s; ratio 6,425x.
  N=44,100: original 6.516362400s; applied 0.000699800s; ratio 9,312x.
At N=44,100 original individual times were 6.5163624, 6.8081234, 5.8104007 seconds.
Applied individual times were .0007274, .0006998, .0004768 seconds.
Ratios describe this filter alone on this machine under contemporaneous load.
They are not measured full-chapter or end-to-end build speedups. No full chapter
was benchmarked or generated by this audit; the maximum signal length was 88,200.

Memory tradeoff
tracemalloc at N=44,100, excluding the preallocated input: original 882,544 bytes;
applied 1,368,155 bytes. The applied code creates padding, a float64 integral, a
subtraction temporary and a division result. Analytical filter-only peak at Ch29
length, including input, is approximately 125.9 MB original vs 201.2 MB applied
(~75.4 MB additional). This is RAM, not disk consumption. The coordinator's
existing disk guard is outside the scope of these measurements.

Domain limits
The replacement is equivalent for finite masks with N>=k and positive k. For
N<k, original NumPy "same" returns max(N,k) samples whereas the replacement
returns N (explicit test: N=3,k=7 gives shapes 7 versus 3). Production cannot
reach this case with nonnegative timeline ends: END=last_end+2s, k=.25s.
NaN/Inf also have different propagation under prefix sums; the production mask
is built solely from finite .42 and .18 constants, so these are not inputs here.
